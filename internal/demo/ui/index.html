1. Handshake (OCPI Credentials)

จับคู่ partner ⇄ Evolt แลก Token A/B/C ตาม OCPI 2.2.1 §7 · Evolt มีแค่ POST (ไม่มี PUT/DELETE ตาม spec) ถ้า party นี้ลงทะเบียนไว้แล้วจะได้ error จนกว่าจะล้างฝั่ง Evolt

Partner เป็นฝ่ายเริ่ม (PlugSiam → Evolt)
Evolt เป็นฝ่ายเริ่ม (Evolt → PlugSiam)
ยกเลิกทะเบียนฝั่ง partner

2. Partner → Evolt

PlugSiam (CPO) ส่งข้อมูลเข้า Evolt (eMSP receiver) และดึงข้อมูลจาก Evolt (CPO sender) · ผลลัพธ์ดูได้ที่แผง Evolt เก็บอะไรของเราไว้ ด้านล่าง

Push location เต็มก้อน (PUT)
Push สถานะหัวชาร์จ (PATCH)
Push / ลบ tariff (PUT · DELETE)
ดึงข้อมูลจริงจาก Evolt (GET + pagination)

3. Evolt → Partner

Evolt เป็นฝ่ายยิง: ดึงผ่าน adapter, fanout tariff, และ event ตู้ชาร์จผ่าน Kafka จริง · ผลลัพธ์ดูได้ที่แผง PlugSiam เก็บอะไรจาก Evolt ด้านล่าง

Evolt ดึงข้อมูล PlugSiam (adapter pull)
Evolt push tariff (fanout เส้นเดียวกับ consumer จริง)
Event ตู้ชาร์จผ่าน Kafka → consumer → PATCH กลับมา
ค่าที่เลือกไปกับ event เฉยๆ — Evolt คำนวณสถานะใหม่จาก DB ตัวเอง (ตู้ dev ออฟไลน์ → บังคับเป็น UNKNOWN) สิ่งที่พิสูจน์ว่าครบวงคือ เวลาอัปเดตของหัวชาร์จขยับ + แถบ PATCH ขึ้น 1000 ในแผงล่าง
ล้างข้อมูล mock กลับค่าเริ่มต้น

📦 ข้อมูลจริงที่แต่ละฝั่งถืออยู่ อัปเดตอัตโนมัติ

แผงนี้คือ "ของจริงในระบบ" ไม่ใช่ผลตอบกลับของ HTTP — ค่าที่เพิ่งเปลี่ยนจะกะพริบสีส้ม ให้เห็นทันที ไม่ต้องเปิด DB

PlugSiam เก็บอะไรจาก Evolt

ข้อมูลที่ Evolt ส่งเข้ามา (fanout tariff / PATCH สถานะจาก Kafka) — คือหน้าจอที่ partner จริงจะเห็น

Evolt เก็บอะไรของ PlugSiam

อ่านกลับจาก partner cache ของ Evolt เอง — พิสูจน์ว่า push เข้าจริง ไม่ใช่แค่ตอบ 1000
